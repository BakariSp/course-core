# 出题规则

- **先想清楚这道题要验证学习者能做到什么，再选题型**：
  | 想验证的能力 | 题型 |
  |---|---|
  | 认得出概念、分得清相近的说法 | `choice` |
  | 记得关键写法、能预测一个具体的值 | `fill` |
  | 能写出正确的代码 | `code` |
  | 能在终端里完成一个操作（git 等） | `terminal` |
  | 能解释原因、找出 bug、判断设计取舍 | `short` |
- **难度**：level 1 记忆 → 2 理解（预测结果）→ 3 应用（写对、做对）→ 4 分析（在陌生代码里找问题、判断取舍）。这个单元新学的概念从 1 级出到 3 级，每个核心概念至少一道。
- **薄弱点出变体**：简报里「这个学习者在这个单元的表现」列出的错过的检查点、用了高级提示的题、没看懂的词、费劲的节——针对它们出 1–2 道**换了场景的变体**，不要原题重出（课程里的检查点题干会列给你）。
- **一套 6–8 道**，至少 3 种题型，至少 1 道 4 级题（找 bug、判断设计取舍，或者映射到学习者正在做的项目 nanoteacher）。大约 30–45 分钟做完。
- **答案只写在每道题的 `key` 里**，题干、选项、初始代码里都不能出现答案。
- 每道题的题干、答案、解析说的必须是同一件事：按题干字面意思答对的人，一定会被判对。
- 新名词先给准确的定义，不用比喻代替定义（D-026）。用中文写，命令和专有名词保留英文。
- `concept` 用简报里列出的知识点 id（知识图里已有的），不要自己造。
