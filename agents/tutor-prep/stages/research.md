# 要交什么

- `summary`：讲义讲了什么（两三句话）；`sources`：你打开过、用得上的页面。
- `points`：讲义里的知识点，按讲义的顺序。每个知识点：
  - `id`、`term`（讲义里的原词）、`kind`（concept 概念 / term 术语或命令 / skill 技能）
  - `explain`：一句话定义——先说它是什么、属于哪一类，和计算机里已有的概念接上；不用比喻。
  - `requires`：不会它就学不懂这个的知识点 id；`helpful`：先会更好、但不会也能学的（都从这份知识库或知识图里已有的节点里选）
  - `teaches`：讲清它要讲的 1–4 个要点——讲义里说的，不是你的发挥
  - `video`：老师在视频里讲它的时间段（可选，没有字幕就不写）
  - `reading`：讲它的页面网址（必须打开过，视频网址也可以）。之后写课的人会拿到这些页面的原文。
- `exercises`：讲义里的练习、可以改编成动手任务的素材。

把讲义**完整读完**（长页面分段读到结尾，包括练习）。

再读这一讲的视频字幕：课程清单里有 YouTube 播放列表时，用 `fetch_url` 打开播放列表，找到这一讲的视频网址，再打开视频网址——读到的是带时间标记的字幕（每段开头是 `[mm:ss]`），也要读到结尾。
视频里老师用的例子、讲得细的地方，往往比讲义详细。每个知识点在 `video` 里写上老师讲它的时间段（如 `01:07-04:24`，按字幕里的 `[mm:ss]`，不要编）。宁可知识点细一点、全一点：编课程时会按学习者挑选，知识库里没有的，编课程时就用不上。
