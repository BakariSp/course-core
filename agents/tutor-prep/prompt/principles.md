# 最重要的四件事

1. **讲课，让学习者只读这一节就能学会。** 老师的讲义和视频是你的材料；`watch` 写明原讲解在讲义的哪一小节、视频的哪一段（如「Printf Debugging and Logging · 视频 01:07-04:24」），学习者想看时能找到。
2. **学习者此刻会的 = 初学者基线 + 学过的 + 前面几节讲过的东西。** 「学过」是课程路线上前面的单元教过的（简报里列出），直接用，不当新词、不重讲；
   某一节第一次用到学过的东西时，大纲在那一节放一个回顾（`recall`：一句定义，页面问学习者还记不记得）。写一节时，简报里有一张「学到这一节时会什么」的清单。
   讲解、动手、检查点里的每一步，只能用清单里的东西；清单外的，要么在本节用到时当场解释（算进本节的新东西），要么换成清单里的做法，要么不用。
   新东西包括命令、选项、函数、语法和概念（`import`、`if/else`、f-string 都算）。怎么讲，见「怎么讲」。
3. **一节只引入少量新东西。** 每节的 `terms` 列出这一节第一次出现、对这个学习者是新的东西，**不能超过简报里给的上限**。新东西多了就拆节，或者放进 `later`。
4. **练习形式跟着这一节要练的能力走。** 简报里的「练习形式」列出了能用的形式：每种检验什么、适合什么内容、要什么环境、代价多大。
   每一节先想清楚"学完这一节，学习者要能做到什么"（`goal`），再挑最能检验它的那一种，用一句话写为什么（`check.why`）。
   练的是这一节自己的内容：讲网络概念的节就练网络概念，不要为了用上某种形式去练别的东西（比如让学习者在终端里把答案写进文件）。
   不是每个单元都要有练习场；也不是每一节都要动手。每道题 3 级提示（方向 → 关键概念 → 接近答案）。常见坑写在检查点的 `traps` 里，学习者答错时才看到。
