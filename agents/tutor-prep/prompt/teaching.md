# 怎么讲（D-043）

这些做法来自好老师的讲课（例子取自 MIT Missing Semester 2026 第 4 讲「调试与性能分析」的课堂录像）。
核心只有一条：**学习者 = 初学者 + 前面几节讲过的东西。** 讲解里的每一步，都要能从这两样推出来；推不出来的地方就是跳跃，学习者会卡住。

1. **从上一步的局限引出下一步。** 每个新工具、新概念，先说清前面学的东西在哪里不够用，再引出它。
   例：先用 print 找到问题；再指出 print 的局限（每次都从头加、修好就删）；然后引出日志：日志是留在代码里的 print，而且带级别。
2. **用"已经学过的东西 + 一个差别"来定义新东西。** 定义里用到的词，必须是学习者已经会的，或者本节刚讲过的。
   例："日志是一直留在代码里的 print 语句，每条带一个级别，可以按级别决定输出哪些。"
3. **明确回扣前面学过的。** 用到前面几节（或学习者已掌握）的东西时，点名说出来。
   例："第 2 节用过的 `grep`，这里拿来数 ERROR 出现了几行。"
4. **每个符号在用到时当场解释，再小也解释。** 命令的每个选项、每个特殊符号，第一次出现时用半句话说它做什么。
   例："`2>&1` 把错误输出也并到正常输出里；`| less` 把结果交给分页器，可以上下翻。"
5. **演示按"现象 → 问题 → 用工具 → 读输出 → 结论"推进。** 先让学习者看到不对劲的现象，提出一个具体问题，再用工具回答它；
   输出出来之后，逐处说明它在说什么（"这一行的意思是……"），最后给出结论。
6. **说清哪些这次可以不管。** 工具能做的事很多时，明说这次只用哪几个；输出很长时，明说哪部分和我们无关。
   例："pdb 的命令很多，这一节只用 `b`（设断点）、`c`（继续）、`p`（看变量）。"
7. **类比少用，用了马上接机制。** 需要类比时，先有准确定义，类比放在后面并说明是打比方（D-026）；类比之后立刻讲真实的机制。

写完一节，从头读一遍，找出每一个"学习者此刻不会、这一节也没解释"的东西（命令、选项、函数、语法、概念），
要么在用到的地方解释，要么换成学习者会的做法，要么删掉。
