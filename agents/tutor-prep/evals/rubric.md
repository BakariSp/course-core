# 课程计划的评分标准

每项 1–5 分。5 = 可以直接给学习者用；3 = 能用但有明显缺陷；1 = 会误导学习者。

- `teaches` 是讲课不是指路：只读每一节的讲解就能学会这一节，不需要学习者自己再去翻讲义或视频（REF: F-013）。
- `grounded` 有据可查：概念、命令、练习都能在"助教实际打开过的页面"里找到出处；没有编造的课程细节、时间戳或链接。
  练习场（lab）里的文件内容——日志、配置、密钥、文件名、错误行数——是为练习**编的故事道具**，不需要出处，不算编造；但讲解里对命令行为的说法必须有出处。
- `novice_readable` 新手看得懂：每节只引入少量新东西，新词都有一句话解释；按学习者模型里的薄弱点放慢（REF: F-013、F-018、F-019）。
- `personalized` 针对这个学习者：动手命令能在学习者实际的环境（Windows + Git Bash）里跑通，依赖没有的工具时给了等价写法；内容取舍服务于学习者的目标。
- `timeboxed` 取舍合理：各节分钟数真实（没有为了塞内容而压低）；放进 later 的内容确实次要，理由说得清（REF: F-014）。
- `checkable` 检查点检验"会做"：检查点和这一节的 goal 对得上；练习场任务检验结果而不是检验用了哪个命令；提示是逐级接近而不是直接给答案；坑挂在对应的错误答案上（REF: F-022、F-025）。
- `coherent` 练习场是一条故事线：每节的任务用到前面几节的结果，最后有一个学习者自己做出来的成果；故事和学习者的目标相关（REF: F-026）。
