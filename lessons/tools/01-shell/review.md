## 核心概念：bash 先处理，程序后运行

**定义**：你敲下一行命令后，bash 先把这一行加工一遍——展开 `*`（glob）、处理引号、打开 `>` 指向的文件——然后才启动程序，把加工好的参数列表交给它。程序只看得到加工后的结果。

| 字符 | 谁处理 | 什么时候 |
|---|---|---|
| `*`、`?`（没加引号） | bash | 启动程序之前，在**当前目录**里匹配文件名 |
| `"..."`、`'...'` | bash | 启动之前去掉引号；引号里的 `*` 不展开 |
| `>`、`<`、`2>` | bash | 启动之前打开文件（`>` 这一步就把文件清空了） |
| `-n`、`ERROR`、`-name` | 程序自己 | bash 原样交过去 |

## 逐题

### q1（0.5）漏了 `>`
你认出了 `*` 是 bash 展开的，但 `>` 也是 bash 的：bash 在启动 grep 之前打开 `work/out.txt`，把 grep 的标准输出接过去，再把 `> work/out.txt` 从参数里拿掉。grep 根本不知道自己在往文件里写。

### q2（0.5）打印内容和参数个数自相矛盾
你填的打印内容是 `a.log b.log c.txt`，参数个数是 3。
- 双引号里的 `"*.txt"` **不展开**，bash 去掉引号后把字面的 `*.txt` 交给 echo，所以打印 `a.log b.log *.txt`。
- 你的答案里，`"*.txt"` 被展开成了 `c.txt`——这说明你还没把"引号 = 告诉 bash 别动它"这条规则用起来。

### q3（0.67）grep 没找到 ≠ 成功
grep 的退出码约定：找到了 0，**没找到 1**，出错 2。"没找到"不是报错，但也不是 0。后两个空你都对了，说明"`$?` 只看上一条命令"已经掌握。

### q5（0）重定向在程序启动之前清空文件
`sort names.txt > names.txt`：bash 先以写入方式打开 `names.txt`（这一步清空了文件），然后才启动 sort；sort 读到的是空文件，结果是 **0 行**。
正确写法：`sort -o names.txt names.txt`（sort 读完再写），或者写到临时文件再 `mv`。这是 AI 写的脚本里常见的 bug。

### q7（0.15）
你的回答："所有备份都没有了""bash 找到了所有的 log 然后全部压缩了"。
1. **cd 失败不停**：`$LOG_DIR` 没设置或目录不存在时，`cd` 失败了，但 bash 默认**继续执行下一行**，`rm *.bak` 就在原来的目录里删文件。修法：`cd "$LOG_DIR" || exit 1` 或 `set -e`。你说"得有个 if 判断"方向是对的，但要判断的是 **cd 的退出码**。
2. **`-name *.log` 没加引号**：bash 在启动 find 之前、在**当前目录**里展开 `*.log`。当前目录有一个 `.log` 时，find 收到的是具体文件名，只找这一个名字；有多个时 find 报参数错误。不是"全部压缩"，恰恰相反。修法：`-name '*.log'`，让 find 自己在每层目录里匹配。
