目前的进度大概在60%，根据产品的持续迭代，prd会发生变化，这个文档里面记录了产品实现与实际需求的gap。

1.职责分工。
理论上，整个repo是由agent + 自动化工具的一个集成系统。在接受用户学习需求等input的情况下，一个能够使用llms(内置）/外部接入agent(如pi:主要是给pi提供harness)来生成知识点，内容讲解，题目练习，并且能够动态记录用户在学习过程中产生的信号（难易度反馈，cognitive load, 题目正确率与实际回答情况等）来提供个性化的课程，从而达到高效与快速提升用户给定学习目标的知识与实践水平的personal learning system. 同时，系统内置eval workflow来评估，优化模型给出的输出结果，实现系统内部对于各个功能的自我优化（比如说prompts, contexts)

定义：root 下 claude.md 与 readme.md 都提到了 agent, teacher, learner模型，本质上不应该存在teacher, 这是因为产品是依赖于agent进行开发，所以利用claude code/pi agent作为与代码库的交互对象，解析开发者的需求, 所以在开发初期，coding agent 会作为teacher与开发者/learner进行互动，而目标是构建一个 general learning os，teacher的角色将被内化为产品的自我 eval 一部分。

2.最小学习闭环。
前期的软件构建目标是实现“最小学习闭环”：
1. 学习内容生成
    a. 用户信息（用户画像，学习记录，环境上下文）
    b. 工程提示词 （对应生成内容的要求与规范）
    c. ？
2. 学习者学习-输入信号（测验结果，对于内容学习难度的评估，学习时长 etc.)
3. 根据信号优化下一节内容 back to 1

优化目的与目标：
1. 工程提示词的优化： 内容生成应当由内部 eval agent 检验，从内容正确性，代码可执行性，教学内容合理性等多个维度进行评估，进行迭代优化。经常出现的问题/重要的问题应当由版本控制下的 prompt 进行迭代优化，目的是减少重新生成/再生成的次数，收敛到一个合格的内容生成。
2. 对于该用户信息的个性化优化： 结合用户的学习信号，结合教学，讲解，练习策略，保证知识的正确性的情况下提高学习效率，控制认知负荷在能够接受的程度，基于用户的水平（动态变化）提供到达最终学习目标的最优路径。

3.使用流程
产品应该具备清晰且有着极简风格的UI，向学习者清晰明确地传达信息。
从目前的形态，应当是：

首页：
正在进行的课程 - cs-study
添加课程 （#to be dev)


cs-study课程页：
    (展示curriculum)
    course 1 : shell (已完成) | 进入课程
    course 2 : git | 生成课程
    course 3: xxx ....
课程大纲目前是与 teacher 讨论生成的，未来可能成为一部分的功能。
最好是按照 完整课程 - parts - section (course?) 来进行命名，相关的部分可以放在一起， 比如说 Part0 : fundation of operations 里面包括 shell, git 等课程。 

CONSIDER: 考虑到随着用户的使用，在 A 时刻生成的课程 C1 时，agent 用到的上下文可能会发生变化，那么如果用户想要知道 agent 生成课程的时候到底看到了什么？最好给生成课程一个次级页面，写了与该课程生成时，agent 看到的信息版本？（是否有必要？） 比如说 agent 可能在 A 时刻看到的是用户没有操作 shell 的基础，而在 B 时刻查看的时候，用户可能已经具备了 shell 的操作基础。这时查看课程 C1 的生成信息，里面的应当是能看到 inputs : user status ，是一个当时的切片？ 

因为课程生成往往包含了大量内容，一次性生成很贵，而且难以改写，考虑里面每个小节单独生成？或者先生成大纲再调整？（也方便 eval 进行审核）
其次，课程生成的界面不应该是点击一个button直接执行整套操作， 最好是用户能够通过 button 触发，manage里面的必要信息，甚至提出要求， 确认后 async 的方式进行生成，更好的办法是，由于 curriculum 是一开始就确定的，在用户学习时，或者后台空闲时可以注册 pending task, 先抓取信息， 虽然用户的学习情况会有变化，但是课件等关键知识 source 可以提前准备。 目的是减少用户等待的时间， 当用户想要进行下一节课学习的时候，内容就准备好给他。 而用户完成了某些部分，如果是连续的，甚至可以根据测评（单元大测评）情况给他进行复习，总体思想是：通过用户的各种信息（学习时间，进度，速度，掌握程度等）预测这个方向上最优的学习路线，并且在学习中动态调整。
