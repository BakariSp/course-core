## 0. 一句话结论

**学习体验这一半已经基本成型（Shell 课程"体感很好"）；系统自己转的那一半还没有——几乎每个"让流程往下走"的动作，都要导师（Claude Code）在对话里触发。**
下一阶段的目标不是加功能，而是把导师从运行时的流程里拿出去：导师只做"开发者的编码助手 + 抽查"，产品内部的出题、审阅、修复、发布、调整路线都由系统里的 agent 和检验器完成。

## 2. 核心问题：哪些地方还得靠导师

逐个对照现在的代码和流程（✋ = 只能导师在对话里做）：

| 环节 | 现在谁触发 / 执行 | 该是谁 | 差距 |
|---|---|---|---|
| 定课程清单（curriculum / syllabus） | ✋ 导师和学习者对话 | 学习者在页面上管理；系统提议路线 | 没有界面 |
| 开始备课 | 面板按钮（D-032）/ ✋ 命令行 | 系统在后台**提前**准备（PRD_V1） | 没有预备任务 |
| 审阅课程 | ✋ 导师读产出、核对评分模型 | 评审模型（D-035） | 在建 |
| 练习场验证 | ✋ 导师读命令后手动跑 | 评审模型放行后自动跑（D-030） | 没接上 |
| 修复 | ✋ 导师改 prompt 后**整份重生成** | 定点修复（D-035） | 引擎已建，没接上 |
| 发布 | ✋ 命令行 | 通过检验自动发布；学过的单元要学习者确认（D-034） | 没做 |
| 标记单元学完 | ✋ 导师改 syllabus | 由证据算出（最后一节检查点通过 = 学完） | **数据重复**：syllabus 的 status 是手写的 |
| 出单元题 | ✋ **导师手写** `lessons/` | 出题 agent，走同一台产出循环 | 完全没有 |
| 批改简答题 | LLM（D-031） | 同左；导师抽查 | ✅ |
| 写批改总结 review.md | ✋ 导师 | 系统从作答证据生成 | 没做 |
| 记录"哪里没懂" | ✋ 导师 `kg observe` | 学习者在页面上标（新词 👍👎 已有）；提问（D-018） | 部分 |
| 课程评测 course-eval | ✋ 命令行 | 单元学完自动跑，结果进改进循环 | 没自动 |
| 根据学习信号调整下一单元 | **没有人做** | 系统（PRD_V1 最小闭环第 3 步） | **完全缺失** |
| 改 prompt / 评测（改进循环） | ✋ 导师 | 优化者提议 + 实验，学习者批准评测改动（D-022） | 规则有，机器没建 |
| 记反馈、提决定 | ✋ 导师 | 导师（这是开发过程，保留） | — |

**14 个环节里，11 个要导师手动；最关键的"学习信号 → 下一单元"没有任何人做。**
这和 PRD_V1 的定义一致地指向同一个问题：CLAUDE.md 里的"导师"混了两个角色——

1. **开发者的编码助手**（Claude Code 改这个仓库）：应该保留。
2. **产品运行时的角色**（出题人、审阅人、发布人、路线规划人）：应该变成系统里的 agent / 检验器，而且每一个都有版本、有评测。

## 4. 想要的产品形态

### 4.1 角色

| 角色 | 是什么 | 做什么 |
|---|---|---|
| **学习者** | 人 | 定目标和课程清单；学；给信号；批准"评测标准"的改动和学过单元的新版本 |
| **系统里的 agent / 检验器** | 有版本、有评测的模型调用 | 规划路线、备课（大纲 → 分节）、出题、批改、审阅、修复、复习 |
| **开发者的编码助手（Claude Code）** | 仓库外部的开发工具 | 改代码、改 prompt 和评测、抽查 agent 的判断；**不在运行时的流程里** |

### 4.2 一个单元的生命周期（全程不需要导师）

```
curriculum 定好（学习者同意一次）──▶ 系统按顺序提前生成后面的单元：大纲 → 分节 → 产出循环 → 发布
                                   （不逐个单元给学习者看大纲；想改随时能改）
                              │
学习者学 C1，每学完一节 ──▶ 调整检查：这一节暴露的薄弱点，和后面已生成的单元（C2 …）有没有关系？
                              │        有 ──▶ 生成"插入物"：一段讲解 / 一道练习，插到 C2 的相关位置
                              │               （插入物也走产出循环；原有小节一个字不改）
                              ▼
学习者打开 C2 ──▶ 看到"和之前有关"：哪条插入物、因为 C1 的哪一处（原话 / 错题）
                              │
                     学习者：进入学习 → 检查点 → 单元题（系统出题、系统批改）
                              │
                     单元学完：自动跑课程评测 → 信号进学习者模型 → 统计进改进循环
```

### 4.2.1 调整 = 插入，不是重新生成（学习者 2026-09-26 确认）

| | 重新生成 | 插入（采用） |
|---|---|---|
| 改动范围 | 整个单元或整节 | 只新增一段讲解或一道练习，原有内容不动 |
| 花费 | 贵（一个单元一次 agent 运行） | 便宜（一次模型调用 + 检验） |
| 进度 | 按版本算的进度会断 | 原有小节不变，进度不断 |
| 可追溯 | 难看出改了什么 | 每条插入物记着"因为 C1 的哪条证据" |
| 和 D-035 的关系 | — | 插入物是一种新产出物；冻结检验天然成立（只加不改） |

- **什么时候检查**：C1 每一节检查点通过时（不是等整个单元学完）。检查本身是一次便宜的判断：这节的证据（错过的检查点、👎 的新词、费劲程度、提问）和后面单元的大纲有没有关系；大多数时候结论是"没关系"，不产生插入物。
- **插到哪**：只插到学习者**还没学过**的小节前面；已学过的小节不动。
- **学习者能改**：打开 C2 时能看到每条插入物和它的来由，可以删掉；也可以在"更多"里要求重新生成（保留，但不是默认路径）。

### 4.3 界面（极简，三层）

1. **首页**：正在进行的课程（cs-study）；以后"添加课程"。
2. **课程页**：按 part 分组的单元列表，每一行只回答"现在能不能学"：
   `Part 0 · 基础操作 ── Shell（已学完 · 复习 / 单元题）｜ Git（能学 · 进入学习）｜ 调试（备课中 · 大纲已好）`
   点开一个单元：大纲、这一版是用什么输入生成的（生成时的切片）、质量检验结果；"更多"里才有重新生成。
3. **学习页**：现在的课程页（讲解 + 练习场 + 检查点），加上学习记录。

开发者视图（流程看板、prompt 版本、运行记录）单独一个入口，学习者平时看不到。

### 4.4 数据上的两处调整

- **"单元学完"改成由证据算出**，syllabus 只保留目标和顺序（不再手写 status）。
- **syllabus 加 part 这一层**：课程 → part → 单元 → 小节。

## 5. 建议的顺序

| 阶段 | 做什么 | 完成的标志 |
|---|---|---|
| **A. 接上产出循环** ✅ | D-035 第 3 步：评审模型（质量 + 命令安全）、自动 lab verify、定点修复、通过即发布 | Git 课程不经过导师，从生成走到能学 |
| **B. 大纲先行 + 分节生成** ✅ | 课程计划拆两段：大纲（学习者可提要求）→ 分节生成，每节单独进产出循环 | 用 flash 也能在 ≤3 轮内通过 |
| **C. 出题 agent** | 单元题也走同一台机器（pytest 先红后绿、答案不泄漏、评审） | 学完 Git 直接开始做系统出的单元题 |
| **D. 信号闭环** | 每学完一节跑调整检查，按 4.2.1 往后面的单元插讲解 / 练习；单元学完自动 course-eval | 打开 C2 时第一次看到"和之前有关"的插入物 |
| **E. 预备任务** | 后台队列：学习时为下一单元抓资料、出大纲 | 点"下一单元"时内容已经在了 |
| **F. 界面重排** | 按 4.3 做首页 / 课程页（part 分组），开发者视图独立 | 学习者 10 秒内知道每个单元能不能学 |
| **G. 改进循环** | D-022 的实验机器；第一个实验：flash vs 更强的模型 | "到达可发布的代价"有数据 |
| **H. 去掉导师** | CLAUDE.md 改写：只剩开发助手的规则 | 学一个完整单元，对话里一次都不用找导师 |

A 是其余所有步骤的前提；B 直接回应 PRD_V1"一次生成太贵、难以改写"和"用便宜模型稳定质量"。
